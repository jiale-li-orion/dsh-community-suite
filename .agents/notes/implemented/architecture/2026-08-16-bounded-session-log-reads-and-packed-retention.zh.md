# Agent Note: 有界 Session 日志读取与打包保留

Status: implemented

[English](2026-08-16-bounded-session-log-reads-and-packed-retention.md) | 中文

## 问题

Session 是仅追加的逻辑事件日志，模型流式输出可以向一个长时间运行的会话加入数百万个 token 大小的 `assistant/chunk` 事件。逻辑事件及其连续 seq 是权威事实，但把每个事件永久表示为常驻 JavaScript 对象，并反复复制完整数组，并不是语义要求。

旧的实时路径混淆了这两件事。每次 append 使缓存失效后，`Session.events` 都会生成完整冻结数组；TokenMeter 等 append 时消费方又会为每个流式事件读取该数组。在一个包含 723 万事件的前缀之后追加 100 次，会在领域工作之前复制约 7.23 亿个引用。冷恢复会把打包 JSONL 行展开成同样以对象为主的表示，历史读取也会为一小页消息实体化并序列化数万个传输分片。由此产生的 CPU 分配、垃圾回收、保留内存和事件循环停顿，会影响 prompt 准入、中断、重新加载以及对 `/compact` 的观察，即使领域操作本身很小。

## 决策

逻辑事件语义继续作为稳定的公开约定；有界读取、私有打包保留和协作式冷工作成为实现基础。

### 稳定逻辑日志切面

`Session.readLog()` 以 O(1) 捕获当前逻辑长度处的不可变 `SessionLogCut`。切面提供经过校验的点读取、正向与反向区间、按类型选择的迭代、具有语义的分片连续段，以及显式 `materialize(from?, to?)`。捕获后的 append 永远不会扩展该切面。`Session.events` 保留为兼容接口，但读取它会显式实体化完整逻辑日志，因此只供结果本质上需要完整数组的操作使用。

实时消费方读取满足需求的最小事实。增量状态使用 `SessionEventFold`：它直接消费送达的 `session/event`，只补齐遗漏前缀，仅在 reducer 成功后推进水位线，并跳过 reducer 声明范围之外的事件类型。点查询使用 `at`；反向搜索与投影使用按类型选择的迭代器。投影单元通过 `eventTypes` 声明同类意图，细化了[会话投影提案](../../proposed/architecture/2026-07-27-session-projection-and-command-log.md)中的驱动。因此，TokenMeter 的 append 工作量保持常数，不再为每个分片取得完整快照。

### 私有打包保留

Session 在私有 `PackedSessionLog` 中存储日志。符合条件的连续分片 delta 共用物理记录，而所有公开读取仍会观察到带原始 seq 与时间戳的独立不可变 `SessionEvent`。紧凑的逐类型区间索引使 `valuesOf` 与 `reverseValuesOf` 能跳过无关类型的记录。打包、区间索引与解码对象缓存都是实现细节：逻辑事件 API、持久事件词汇和 `SESSION_FORMAT_VERSION` 均不改变。

JSONL 读取器把已验证的存储记录转移给 `Session.fromRestoreRecordsAsync()`。Session 接管打包行而不展开其中的成员，并在接管后释放 parser 数组中的对应槽位。按行存储的后端仍可返回普通事件；两种表示产生相同的逻辑日志。`SessionInspection.log` 是主要不可变读取接口，`SessionInspection.events` 则惰性实体化完整兼容数组。该决策扩展了[打包 JSONL 布局](2026-07-26-packed-chunk-rows-by-default.md)、[大型会话恢复流水线](2026-08-05-large-session-jsonl-restore-pipeline.md)和[可复用 Session 准备阶段](2026-08-05-session-preparation.md)，但不会把它们的物理表示变成公开约定。

### 协作式冷工作

必须检查完整产物的冷工作会周期性让出宿主事件循环。Zstandard 帧遍历、明文与撕裂帧 JSONL 扫描、存储记录准入以及最坏情况下的附件授权扫描，都使用累计 CPU 时间预算，而不是固定记录数。单次原生编解码操作或 `JSON.parse` 仍不可分割，因此该策略限制的是自然边界之间的不间断工作，而不是承诺严格的挂钟截止时间。

### 有界历史投影

`session.history` 捕获一个稳定切面，通过反向按类型迭代定位页面，并且只实体化该连续持久区间。协议响应随后投影已完成对话不再需要的传输细节：已完成的 Assistant 流保留首个携带 token 的 delta、usage 分片和最终消息；未完成的 delta 连续段会合并相邻片段，同时保留首 token 与可见内容的计时边界。当 `event.seq` 表示最后一个持久 seq 时，`HistoryEntry.firstSeq` 记录该项表示的第一个持久 seq，使分页、重连修复和未经修改的实时尾部仍然具有精确的 seq 覆盖范围。

### 先归因，再增加观测

优化后的 `/compact` 追踪会区分本地准入、提供方摘要和本地结算。在实测长会话中，准入耗时 7 ms，提供方工作耗时 30.179 秒，提交与结算耗时 4 ms，同时并发静态请求保持响应。因此，剩余命令时长属于提供方延迟，并不支持把 Session 工作迁移到另一种执行模型。移除本地停顿后没有复现 HTTP 408；只有该症状再次出现并能指向具体失败载体时，才增加签发方级别的截止时间观测。

## 验证

参考日志包含 741 万个逻辑事件，私有保留记录约为 82,800 条，而不是每个逻辑事件一个对象。默认历史响应从约 10.68 MiB、61,343 个事件降至约 843 KiB 的 seq 跨度保持条目。冷 JSONL 检查从 16.96 秒降至约 3.0 秒，冷 rename 从 24.948 秒降至 7.465 秒。协作式恢复期间，抽样静态请求的最大延迟从 3,317 ms、144 次中 49 次超过一秒，降至最大 810 ms、145 次中无一次超过一秒；预热后静态请求 p95 为 172 ms，最大值为 274 ms。

测试覆盖稳定切面的不可变性与区间校验、打包和展开表示等价性、稀疏类型读取、分片连续段边界、恢复时槽位释放与让出、折叠重试语义、投影水位线、历史 seq 跨度、未完成流计时、fork 与附件授权、HMR（热模块替换）接管、持久化修复，以及客户端分页与实时尾部拼接。

## 考虑过的替代方案

**保留完整事件数组并改进快照缓存。** 不采用，因为每次 append 都会使完整快照失效；即使降低复制频率，永久保留数百万个事件对象仍是主要内存成本。稳定切面表达真实读取需求，并使存储表示可以独立演进。

**把 Session 恢复与折叠移入 worker thread。** 不作为主要设计，因为实时 Session 及其插件状态无法跨线程传递。把数百万事件 structured clone 回宿主，会重新引入本次要消除的展开、分配与内存压力；在 worker 中重建所有消费方，又会把产品所有权迁移到类似进程间消息的接口上。如果未来单次不可分割的编解码操作成为主因，编解码器仍可单独使用 worker；有界宿主线程工作与打包所有权已经解决实测瓶颈，无需复制 Session 状态。

**在逻辑日志中合并或删除分片事件。** 不采用，因为分片 seq、实时传递、消息来源、计时、取消证据和回放保真度都属于持久语义。物理打包与历史投影可以在不改变这些事实的前提下降低表示成本。

**增加消费方专用的完整日志缓存。** 不采用，因为这会复制水位线与失效规则，保留多份派生表示，并使新消费方很可能再次犯同样错误。`SessionLogCut`、按类型索引和 `SessionEventFold` 是成本显式的共享原语。

**在改变数据路径前提高超时或增加宽泛请求计时。** 不采用，因为更长截止时间不会减少 CPU 独占或载荷大小。性能剖析与持久事件时间戳已经识别本地阶段和提供方阶段；观测应服务于仍无法解释的残余症状，而不是替代已知工作的移除。

## 后果

与请求区间或相关事件类型成正比的操作，不再退化为与会话总长度成正比。append 时 reducer 的成本不随日志长度增长，冷恢复保持事件循环协作性，活跃 Session 保留压缩分片连续段，同时不改变逻辑回放。

成本变得显式。调用 `materialize()` 或读取 `Session.events` 的消费方会为每个选中的逻辑事件付费；随机读取打包分片时也可能分配解码后的事件对象。私有日志与索引增加了 `dsh-session` 内部的实现复杂度，但消费方更简单，因为它们表达点、区间、类型或折叠意图，而不自行管理快照。

协作式让出改善响应性，但不会减少验证冷产物所需的总 CPU，而且单个编解码帧或 JSON 记录仍可能超过目标间隔。历史是传输投影，而不是持久区间的逐字节副本；需要规范账本的消费方使用持久化导出或显式完整逻辑读取。
