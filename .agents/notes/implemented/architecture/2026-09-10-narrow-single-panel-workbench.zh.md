# Agent Note：窄屏单面板工作台呈现

Status: implemented

[English](2026-09-10-narrow-single-panel-workbench.md) | 中文

> 范围：AppFrame 在侧边栏自动折叠断点以下如何呈现工作台，以及为什么这层呈现可以**读**共享的工作台视图、却永远不写它。

## 问题

在自动折叠断点以下，让步链容不下会话栏与工作台栏并存：侧栏轨道加 `CENTER_MIN` 再加 `WORKBENCH_MIN` 就已经超过视口，于是求解器把工作台推导为 0 宽，`WorkbenchShell` 什么都不渲染。结果是会话头部的开关在这个客户端上看起来毫无作用，而它其实已经提交了共享视图——手机点一下，PC 那边打开了面板，手机上什么都没有。

## 决定

断点以下，打开的工作台成为**单面板**：外壳降为两条轨道，工作台占用侧栏旁的那条轨道，会话栏以 `display: none` 保持挂载，因此返回时它的会话状态还在。返回会话由外壳自己的关闭控件完成。

这层呈现**只读**共享的工作台偏好、从不写它。视口变化——旋转、窗口缩放——不会打开、关闭或改选另一端正在显示的工作台；只有人的手势才提交，且仍走 host 服务。没有引入新断点：窄屏状态沿用既有的 `SIDEBAR_AUTO_COLLAPSE` 判定。

## 考虑过的替代方案

- **让求解器给工作台一个最小宽度、把会话栏压到下限以下**——破坏让步契约与宽屏布局。
- **把工作台叠加在会话栏之上**——在外壳的几何所有权之外另开一条呈现通道。
- **视口变窄时自动关闭工作台**——用本地视口变化写共享状态，单权威规则不允许。

共享视图的权威仍归[工作台共享视图](../feature/2026-09-09-workbench-shared-view.md)；本篇只补上那份 note 已经拥有的视图在窄屏下的呈现方式。

## 后果

- 显示单面板时 `gridTemplateColumns` 是两条轨道；占满框架的面板不再提供拖动手柄，详情栏在这个尺寸下没有宽度可占。
- 宽视口保持四栏让步链不变。
- 窄屏而其它栏打开时仍会隐藏它们；详情栏只在宽屏布局里呈现。

## 验证

`packages/client/ui-layout/tests/app-frame.client.spec.tsx` 覆盖：这层呈现本身、关闭后回到四栏、视口缩放而不写偏好、重新变宽后恢复共享宽度，以及不出现拖动手柄。
