# Agent Note: 会话上下文管理：代际、范围压缩、改写与召回

Status: implemented

[English](2026-08-16-session-context-management.md) | 中文

## 问题

仅追加的 Session 日志保留每一项持久事实，Session 表层则选择下一次模型请求使用的消息。Chat 展示仅追加来源的人类记录，Trajectory 展示执行账本，但两者都不能告诉用户哪些消息仍占用当前模型上下文，也不能在不删除历史的前提下修改该上下文。

当两个可独立寻址的 Agent 都需要继续时，fork 是正确选择；若用户只是修正较早提示词并在同一个 Session 身份下继续，fork 会带来多余开销。反过来，如果只替换该提示词，却静默保留根据旧值生成的回答，活跃上下文就会产生因果不一致。

压缩会在日志中保留被遮蔽事件，但提供方工作与表层变更原本位于同一操作中，没有持久的评审状态。人工无法在摘要替换所选历史之前检查或编辑它，人和模型也都没有返回准确被遮蔽消息的有界路径。

## 决策

会话上下文管理是建立在仅追加日志之上的统一能力。Chat 保持完整的仅追加来源 transcript（文本记录），Context 展示下一次请求使用的准确持久对话表层，Trajectory 保持完整执行账本。上下文变更只会追加替换事件与生命周期事件，绝不编辑或删除既有记录。

### 稳定上下文快照

`Session.readSurface()` 捕获不可变的 `SessionSurfaceCut`：一份稳定的 `SessionLogCut`、其逻辑 revision、当前替换次数与替换 seq，以及冻结的有序当前表层 seq 列表。后续追加不会扩展该日志读取器或节点列表；在下一次追加前，重复读取会复用同一 cut。

`ctx.sessionContext.inspect(agent, request)` 把该表层分组成工具配对平衡的单元。一个单元不能把 assistant 工具调用与其结果拆开。响应包含有界预览、位置 token 价格、已路由提供方／模型元数据、单元总数和从尾部开始的分页。`readUnit()` 按点读取一个当前单元的完整消息，并拒绝陈旧身份。

代际是派生状态，而不是另一份 transcript。初始表层是第零代；每次位置替换都会递增 `replaceGeneration`，并在 `generationSeq` 中记录对应的替换事件。日志回放会重建同一代际序列。

### 同 Session 改写与继续

只有用户编写的消息和先前的 session-context 改写可以编辑。宿主保留已授权的图片块，客户端只提交替换文字。

`edit-and-continue` 替换选中单元到当前表层尾部。依赖旧内容的后续记录仍保留在 Chat 与 Trajectory 中，但会离开活跃模型表层。`patch` 只替换选中的平衡单元并保留后缀；UI 要求用户显式确认后续回答基于旧值生成这一风险。

两种模式都会在空闲 Agent maintenance 中校验选中单元和预期尾部，追加替换 `user/message`，追加包含准确被遮蔽成员关系与 token 价格的 `context/rewrite`，然后在返回前 flush。文件、子进程、审批、后台任务、目标、设置、凭据和其他外部状态都不会回滚。

继续操作绝不会伪造 `continue` 一类用户消息。`ContextRunAgent.runFromContext()` 追加持久的 `agent/context-run/requested` 记录，并针对已提交的替换代际排入一个无新消息轮次。agent loop 会持久地认领或取消该请求，保证其顺序早于之后排队的轮次，在重启后恢复尚未认领的请求，并在不打开空轮次的情况下取消已陈旧的恢复请求。

### 可评审的范围压缩

范围压缩包含两个持久阶段。Preparation 记录所选端点、有序成员 digest、token 价格、单元数、保留说明、模型容量计划、确定性的 direct 或 map/reduce 分片、每次调用尝试、每次成功提供方调用和生成摘要。它不会修改表层，可在重连后恢复，也可以编辑、重新生成、丢弃或提交。

Preparation 会解析准确摘要模型的组合上下文窗口与最大输出能力。其默认输出目标是 `min(128k, max(16k, ceil(selectedTokens / 4)))`，再受模型能力限制。只要完整位置局部请求的指令、输入与输出上限能够放入窗口，系统就只运行一次 `direct` 调用；只有超窗请求才使用按容量推导的 map 分片与有界并发 reduction。位置局部提示词会记录结果、决策与约束、产物与状态变更、命令与错误、仍然有效的后台事实、源于该范围的未完成事项，以及字面锚点；它不会从中间区段推断整个对话的当前任务。

Commit 是一次短暂的重新校验操作。它要求当前端点、有序成员关系、digest、token 价格和工具配对均未变化，并要求带框架的摘要小于所选内容。随后它使用标准的 `compaction/start` → `compaction/summary` → 替换检查点 → `compaction/end` bracket，并在释放空闲准入前 flush。所选范围之外的追加仍然有效；范围内部的任何变更都会使 preparation 陈旧。

`CompactionDirectory` 会解析准确 Agent 组合所选择的提供方，并为非隔离部署保留进程级 fallback。人工范围评审与面向模型的 preparation 工具使用同一 preparation/commit API。自动压力压缩、溢出恢复与 `/compact` 继续各自选择范围，但共享同一标准 bracket、工具平衡规则、检查点来源、token meter 与所选范围校验原语。

### 检查点召回

`historyRead()` 与 `historySearch()` 遍历 `compaction/summary.shadowedSeqs`，并可选择进入嵌套检查点。它们读取一份稳定日志 cut，拒绝缺失或重复的检查点身份，保留既有附件引用，而且不需要伴随历史存储。

召回文本由借用的消息块片段组装，不会在每一页都序列化整条消息。读取对完整响应执行字节上限，并且只在字素簇边界拆分。搜索扫描有界 UTF-8 前缀，保留 Unicode 标量边界和跨页字面匹配重叠，并把不透明游标绑定到检查点、递归选项、操作、查询与大小写模式。把游标用于其他查询会失败。

Web 详情面板向用户暴露同一套递归读取与字面搜索。面向模型的 `history_read` 和 `history_search` 工具返回普通工具结果，因此被召回内容会通过正常的模型可见路径进入仅追加尾部。

### 产品与包所有权

Web 对话视图环把 Context 放在 Chat 与 Trajectory 之间。Context 视图虚拟化当前单元、分页读取较早单元、展示对话／系统／工具 token 估算、评审已准备摘要、编辑当前消息，并召回检查点原文。每行都有明确的选择控件；范围始终连续，选择栏可以把第一个选中单元扩展到当前尾部。每条可编辑的用户提示词都有直接编辑操作，助手消息、后台注入、检查点与工具交换仍为只读。Preparation 准入、实时进度、失败诊断、编辑、重新生成与提交始终位于同一个滚动有界且操作区固定的 modal。关闭它会保留持久 preparation 与本地草稿；页头操作可在不改变列表位置的情况下重新打开。只有当较早页的代际和单元区间仍能与已加载尾部相接时，才会把它前插；并发上下文变更会触发新的尾页读取。Chat 渲染持久改写标记，Trajectory 渲染 preparation、改写与 context-run 生命周期记录。

`@deepseek-ai/dsh-session-context` 负责宿主服务与生成的 Remote API。`@deepseek-ai/dsh-tool-session-context` 负责模型工具。`@deepseek-ai/dsh-client-ui-context` 负责 Context 视图与改写标记。Core Session 负责稳定 cut 与代际状态；Agent／AgentLoop 负责 context-run 准入；压缩包负责提供方无关的 preparation 记录与 basic map/reduce 提供方。

### 性能约定

检查和修改绝不读取 `Session.events`、实体化完整逻辑日志，或解码无关的打包分片。单元发现使用稳定表层 cut 和缓存的工具平衡位置。Token 读取使用 `measureRange()`，只复制展示或选择的位置。Preparation 与 commit 的成本和所选范围成正比；无关保留上下文不会进入请求，可直接放入窗口的选择只发出一次提供方调用。召回工作和返回或扫描的字节预算成正比，而不是和完整被遮蔽消息成正比。

一份包含 50,000 个单元的合成表层可在 91.30 ms 内返回最后 200 个单元，快照为 44,840 字节，单元点读为 2.58 ms。对一条 16 MiB 原文读取二十页 64 KiB 数据，共返回 1,303,435 字节，耗时 175.78 ms；十七次 1 MiB 搜索页可在总计 48.78 ms 内抵达尾部字面量。

## 验证

单元与组合测试固定了稳定 cut、代际回放、范围计价、工具平衡、direct-fit 规划、map/reduce fallback、持久调用尝试、preparation 恢复、陈旧提交拒绝、图片保留、持久 context-run 顺序与重启、Unicode 安全召回、查询绑定游标、Remote 生成、插件 dispose，以及 Context 控制器竞态。一个已构建 Web 快照会重新打开持久评审 modal，再通过已发布组合实际驱动摘要提交、检查点读取／搜索、编辑并继续、Chat 标记和回放模型响应。

## 考虑过的替代方案

**给 `/compact` 增加 start/end 参数。** 命令文本是不透明当前单元身份的无类型传输方式，也无法负责交互式评审、改写或召回。`/compact` 继续作为压缩能力的一种人工消费方。

**删除或重写旧日志记录。** 这会破坏请求重建、审计、附件来源和人类历史。表层替换可以表达活跃上下文变更，同时保留持久事实。

**每次修正都 fork。** fork 继续用于另一个实时 Agent 或执行世界。同 Session 改写可以避免普通修正产生列表、标题、导航和生命周期开销。

**修补一条消息并始终保留后缀。** 后续回答可能依赖旧消息。Patch 保留为显式且需风险确认的操作；edit-and-continue 是安全默认值。

**用伪造用户消息唤醒 agent loop。** 隐藏指令会改变请求，并把用户没有说过的文字归因给用户。持久 context-run 工作可以在不增加文字的情况下，从已提交代际授权一次请求。

**交付带冻结索引存根和单一可变状态检查点的第二套可召回压缩后端。** [已拒绝设计](../../rejected/feature/2026-07-06-recallable-compaction.md)会让可达性依赖另一套保留算法，并用索引永久扩大提示词。准确来源与召回应适用于每个标准检查点，并属于共享上下文能力。

**从已分页 Chat 窗口派生 Context。** Chat 会保留已遮蔽的仅追加来源历史，并且可能省略较早页面。Context 必须从权威的当前 Session 表层派生。

**为每次所选范围摘要发送完整对话前缀。** 中间区段工作会随无关保留历史增长，并诱使摘要器声明不属于替换范围的全局状态。位置局部文档让成本与语义都和所选范围成正比。

**始终把可评审范围拆成固定大小的 map/reduce 调用。** 固定分片大小会忽略所选模型的实际容量，为本可直接放入窗口的请求成倍增加调用，还可能让细节密集的 map 输出在无关的小上限处截断。模型元数据决定能否直接放入窗口；map/reduce 只服务真正超过该准确窗口的请求。

## 结果与代价

用户可以检查并主动修改模型的活跃历史，同时保留 Chat 与 Trajectory 证据。摘要评审不会在提供方工作期间占用轮次准入，反复压缩后仍可读取准确原文。模型也可以通过工具执行同样的有界检查、preparation、commit 与召回。

代价是新增持久生命周期词汇、宿主 Remote 能力、一个 Web 视图、模型能力元数据，以及更显式的陈旧状态处理。改写无法撤销外部副作用。已评审摘要仍可能遗漏信息，因此原文召回与保留说明只能降低风险，不能让压缩无损。超过摘要模型容量的选择仍可能需要多次提供方调用；有界并发会限制活跃工作，但不会消除提供方延迟。当前召回仅支持会话内字面查询；语义或跨会话检索需要独立决策。
