# Agent Note: 重放前验证持久化上传记录

Status: implemented

[English](2026-09-11-ingest-record-validation.md) | 中文

## Problem

上传 ID 来自 HTTP 请求，接收索引是可编辑的工作区 JSON。对象属性查找可能把继承的名称误认成已完成上传；接受所有 JSON 对象还会使数组丢失新赋值的记录，并让字段不完整的条目返回虚假的成功响应。

## Decision

上传路由把 JSON 自有条目读入 Map，并在重放前逐条验证接收记录。有效元数据包含非负安全整数字节数和时间戳、SHA-256 十六进制摘要、已知来源类别或 `unknown`，以及该类别上传目录下的纯文件名。无效条目独立忽略，保留可用记录。Object.fromEntries 把 ID 序列化为 JSON 自有键，包括 `__proto__`。

## Alternatives considered

**保留 JavaScript 属性名。** 不采用，因为不透明上传 ID 与对象原型无关；禁止少数字符串也不能解决磁盘数据验证问题。

**一条记录无效时丢弃整个索引。** 不采用，因为这会抹掉其它上传可用的重试记录。

## Consequences

经过验证的已完成记录支持顺序重试，返回相同路径和字节数。忽略不可用元数据保留了现有上传兜底行为，但不能保证索引损坏后的幂等性。本改动不串行化并发上传，不事务提交文件与索引，也不验证记录中的字节是否仍存在。这些恢复要求仍属于后续 E2 工作。

## Testing

真实 HTTP 路由用例覆盖原型属性名 ID、数组索引、无效记录字段及路径与来源不匹配。正式 Web 组合在 `apps/web/tests/upload-ingest.e2e.ts` 中保存无模型调用的上传响应快照，也证明有效记录能与无效条目共存。
