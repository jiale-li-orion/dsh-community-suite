# Agent Note: 社区套件布局

Status: implemented

[English](2026-08-19-community-suite-layout.md) | 中文

## 问题

归档会话 bundle 和锚定预设需要可复现的 rc.7 分发方式，同时不能成为官方 workspace package，也不能修改用户未选择的 profile。它们的源码历史还需要简洁、持久的记录，使后续更新可以区分官方代码、导入改动和本地兼容工作。

## 决策

仓库将社区代码保留在 `community/` 下。归档会话模块仍是位于仓库外构建图之外的 bundle，安装器只会将其添加到 `web` profile。7 个锚定模式仍是复制到 `.agent-presets` 下的运行时组合，而不是 workspace member、package dependency 或官方 profile。

安装器暂存预设，为每个已发布目录标记 `dsh-community-suite` 所有权，并拒绝已有目标，除非 `--update` 指向自有安装。它在替换自有预设或 Web profile 文件前保留备份，不枚举、读取或写入 sessions 目录。

`COMMUNITY_SOURCES.md` 记录固定的官方 rc.7 基线、leavelet 的 7 个会话上下文提交，以及归档会话和锚定预设的源码修订与本地适配。仓库以一个根快照提交开始，没有导入的父提交。这段简洁的分发历史使后续导入评审可以查看明确的修订和适配范围，而不是从复制文件中推断。

## 核验

`pnpm run community:check` 运行安装器测试、归档会话 bundle 测试，以及锚定预设的同步检查和 Node 测试。安装器测试覆盖仅限 Web 的 bundle 调用、7 个公开预设标识、所有权检查、更新备份、回滚和 sessions 目录禁止访问。文档检查保持源码链接、双语记录、Agent Note 结构和生成的第三方声明有效。

## 曾考虑的替代方案

- **将模块加入官方 workspace 图**：不予采纳。workspace 成员资格会使社区 package 成为官方构建与依赖闭包的一部分，掩盖其独立的兼容性和支持范围。
- **将预设安装为官方 profile**：不予采纳。预设选择是用户级运行时组合；将它们发布为官方 profile 会在没有单独产品决策的情况下扩大默认产品。
- **无条件覆盖同名预设**：不予采纳。名称本身不能证明所有权。标记加显式 `--update` 可保护用户管理的目录或其他来源的目录。
- **只在生成的声明或复制的源码头中记录来源**：不予采纳。生成的声明描述依赖，源码头容易漂移，二者都没有说明 rc.7 适配范围。简短的源码记录使导入决策可供评审。
- **保留或导入三个来源的完整历史**：不予采纳。不相关的父图会把可分发的 rc.7 快照变成历史集成项目。源码记录保留维护所需的修订和适配边界，而不把复制的祖先关系呈现为本仓库的开发历史。

## 后果

官方 workspace 和默认 profile 保持专注于官方代码，用户则可通过一个经过检查的入口安装社区模块。此布局放弃了社区代码的自动 workspace 构建、发布和兼容性承诺；当其来源或 rc.7 适配发生变化时，维护者必须更新快照记录并重新运行聚焦检查。
