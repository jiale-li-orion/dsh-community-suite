# E2 设计：设备来源对模型可见 + 文件上传（待确认）

日期：2026-09-11。范围：E2「内容接入闭环」的第一个切片。

## 1. 现状（已核对代码，不是推测）

上行链路：

```
客户端 UI → api.sessions.prompt({...})        ← packages/client/runtime/.../session.ts:192
          → host RPC（session.prompt）
          → agent.send()                       ← packages/core/agent-loop/src/agent.ts:317
          → session.append('user/message', …)  ← 模型可见的唯一入账点
```

结论：**这条链上没有"来自哪个连接/设备"的信息**。用户当前看到的模型（我）只知道消息文本与附件——这就是用户指出"这个功能需要加一下"的缺口。

可复用的既有机制：
- `user/message` 事件已带**结构化 `source`**（如 `{kind:'plugin',plugin:'session-context'}`、`{kind:'context-rewrite'}`）——已有"谁产生了这个事件"的先例；
- `packages/context/*` 是**请求上下文插件**（time-context、agent-instructions 等），是"给模型看的东西"的正规承载点。

## 2. 三个候选设备信号（需要选一个，这是本文档要你确认的点）

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| **A. 薄壳自报（推荐）** | App 的回环网关在每个上行请求加一个标记头（它本来就在重写请求）；host 在握手时读该头，绑到"这条连接" | 明确、可控、不依赖外部系统；网页端天然是默认值 | 只覆盖我们自己的 App；手机浏览器打开网页时仍算"网页" |
| B. Tailscale 身份 | 用 tailscaled 注入的 `Tailscale-User-*` 头 | 不用改客户端 | **只有用户身份，没有设备名**；按 IP 应急入口没有该头；语义不稳 |
| C. 服务端猜 | 按 remote address / User-Agent 推断 | 零改动 | 猜错就是**假信息进模型上下文**——比"不知道"更糟 |

**我的建议：A + 网页端自报平台。** 具体：
- App：网关加 `X-Dsh-Shell: android`（以及设备型号，便于区分多台手机）；
- 网页：客户端上报粗粒度平台（`standalone` + UA-CH 平台），人机可读，不猜；
- 两者都缺失时**如实标注"未知来源"**，绝不编造。

## 3. 数据如何流到模型（符合"模型可见 ⟺ 已记录"）

1. **传输层**：host 在连接建立时确定设备标签，放进**每请求的上下文**；
2. **入账**：`agent.send()` 追加 `user/message` 时，把设备来源写进事件数据（新增可选字段 `origin`）。这样"模型看到来源"完全可由日志重建；
3. **投影**：用户消息投影到模型请求时带上来源标注（例如"（来自手机 App）"）。心跳、重连、状态推送等**非消息流量不进上下文**；
4. **未知即未知**：取不到来源时写 `unknown`，不伪装。

## 4. 文件上传（本轮第二个切片，待上面确认后做）

- 手机：`<input type=file>`（App 已接好系统文件选择器）→ 上传到会话工作区 → 作为附件进消息；
- 电脑：拖拽 / 选择文件，同一条链；
- **来源影响处理**：手机上传的照片要标注"来自手机相机/相册"，电脑上传的代码文件标注"来自电脑"——这正是第 3 节要先把来源做通的原因；
- 附件落盘位置：会话工作区内的受控目录（不污染仓库），并在消息里保留可回溯的引用。
