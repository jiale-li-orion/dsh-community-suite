# 移动端布局规格 v0.1（待确认）

日期：2026-09-11。目的：**在动手前把窄屏的信息层级和控件归属定死**，避免继续"发现一处补一处"。
范围：窄屏（视口 < 1024px，与 `SIDEBAR_AUTO_COLLAPSE` 同一个断点）。PC 四栏排列**不改**。

## 1. 一条原则：同一批座位，两种排列

手机不是另一套应用，而是**同一批 UI 座位（会话／列表／工作台／详情）的另一种编排**。
- 座位声明权仍归 `ui-layout`（渲染未声明的座位会在加载期报错，所以"新插件接管整个界面"这条路走不通）；
- 手机上**一次只显示一个页面**；PC 上四栏并存；
- **页面是本地导航**：另一端开关工作台**不许**推动本机页面（已修）；本机点工作台**会**提交共享视图，让 PC 跟随（保留你喜欢的"远控"感）。

## 2. 页面模型（只有三页）

| 页 | 内容 | 进入方式 | 返回方式 |
| --- | --- | --- | --- |
| **会话**（默认主页） | 当前会话的对话、视图标签（对话/上下文/轨迹）、输入框 | 启动即在此；从列表选中会话后回到此页 | — |
| **会话列表**（左导航） | 全屏的会话列表：按工作区分组、底部主题与设置 | 横条左键（`☰`） | 横条左键（变 `←`） |
| **工作台** | 当前会话工作区的 artifacts：文件／插件市场／主题 | 横条右键（`工作台`） | 横条左键（`←`）→ 会话 |

三页**全部保持挂载**，只是可见性切换：切页不丢会话滚动位置、不丢文件面板目录。

## 3. 顶部横条（唯一的顶栏）

```
[ ☰ / ← ]   会话名称（过长省略）   [ 工作台 ]
```

- **左键随页面变义**：会话页＝`☰` 打开列表；其它页＝`←` 返回会话。两个方向都只需一次点击，都有 `aria-label`。
- **中间是当前会话名**；无会话时显示本地化占位（不显示 `sessionId`）。
- **右键由工作台插件贡献**（它才拥有共享视图权威），标签「工作台」。
- **安全区**：横条 padding 与正文底部都用 `env(safe-area-inset-*)`，`index.html` 带 `viewport-fit=cover`。**被系统状态栏挡住的按键等于按不到**。

## 4. 控件归属（谁在手机上显示、谁被隐藏）

| 控件 | 归属 | 窄屏 | 理由 |
| --- | --- | --- | --- |
| 页横条（三件套） | `ui-layout`（外壳） | **显示** | 唯一的顶栏 |
| 工作台开关 | `ui-workbench` | **只在横条**（会话头部那份隐藏） | 同一手势不该出现两次 |
| 侧边栏收起 | `ui-sidebar` | **隐藏** | 列表页本身就是那一页，没有"可收起的侧边栏" |
| 会话面包屑（会话名） | `ui-conversation` | **隐藏** | 横条已经显示同一个名字 |
| 视图标签（对话/上下文/轨迹） | `ui-conversation` | **保留** | 不是重复，是不同维度 |
| 权限预设 / Session log / 子代理目录 | 各自插件 | **保留** | 手机上也用得到 |
| 详情栏（会话详情/轨迹） | `ui-layout` | **暂不呈现** | 你列的三页里没有它；要的话并入左导航页 |

## 5. 文件预览：宽屏分屏、窄屏整页

| 工作台列宽 | 行为 |
| --- | --- |
| ≥ 640px（PC） | **面板与预览并排**：左文件树、右预览 |
| < 640px（手机） | **预览整页覆盖面板**，头部只有 `← 返回工作台`（不再有第二个 `×`） |

**高度契约**（当前未达标，见第 8 节）：pushed 模式下 `shell → panes → viewer → viewerBody → 渲染器` 每一层都必须有确定高度，渲染器自身 `height:100%`，文档类预览 `align-self: stretch`（`.viewerBody` 的居中是为图片/视频准备的，会把文档吊在半空并截断）。

## 6. 空状态与异常状态（都要有明确呈现）

| 情形 | 呈现 |
| --- | --- |
| 无会话（hero） | 会话页显示 hero + 输入框；横条显示占位标题 |
| 会话列表为空 | 列表页显示空态文案 + 「新建会话」 |
| 工作区为空 | 文件面板显示空态文案 |
| 连接断开 | `shell.overlay` 顶部横幅「连接已断开，正在重连…」；恢复后消失。**不自动重发/重批/安装** |
| 插件加载失败 | 启动页列出失败条目（`Failed to load plugins`），不显示半成品 UI |
| 文件读取失败 | 预览区显示失败原因（含 HTTP 状态），不显示空白 |

## 7. 明确不做（这一版）

- 手机上的详情栏入口；
- 离线会话缓存 / Service Worker（否则必须另行定义失效规则）；
- 手机端 App 内原生 PDF 渲染（pdf.js 会拖慢启动，或走 Android 原生 `PdfRenderer`，待定）；
- PC 布局的任何改动。

## 8. 未达标项（如实列出，规格确认后一并修）

1. **文件预览高度**：pushed 模式下预览容器实测仅 **379px**（页面可用约 700px），文档在 379px 处被截断、下方留白。**PC 上同样存在**。需继续查 slot 链路包装层的高度约束。
2. **主题面板「外观操作失败」**：配置缺失，不是代码 bug。修法：`~/.dsh/profiles/web/cordis.patch.yml` 的 `plugin-install` 行加 `config: { profile: web }`，**重启后生效**。
3. **手机安全区**：无头浏览器没有系统状态栏，只能靠代码正确性 + 真机截图间接确认；需要在真机上按一次横条按键确认未被遮挡。

## 9. 已确认（2026-09-11）

1. **三页够用**；详情栏**并入左导航页**（不单独成页）。
2. 横条右键标签用**「工作台」**（后期还要往上加功能）。
3. hero／初屏要改，三点具体：**① 输入框不在最底部**（要么贴底，要么初屏纯插画不显示输入框）；**② 模型 ID 与其他 UI 重合**；**③ 整页太大**——需要真正的「页面缩小」能力（这也是鲸鱼标识挡住插画人脸、两张背景插画重叠的直接原因）。
4. 手机端 PDF **交给系统应用打开**（不做 App 内原生渲染）。

### 由此新增的规格条目

- **界面缩放**：手机端必须有可用的"缩小"能力，且**默认值就该更小**（不是全靠用户手动缩）。承载点：外观偏好（与主题同源），作用于文档根，**浏览器与 APK 一致生效**。
- **初屏输入框**：窄屏贴底；若与插画冲突，则初屏只留插画与标题。
- **模型选择器**：不得与相邻控件重叠（窄屏下需要单独一行或收窄）。
